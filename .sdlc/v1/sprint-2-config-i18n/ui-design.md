# PART 1 — HUMAN REVIEW

## Concept (plain description)

Today each `text`/`textarea` field on an admin settings page renders a single input. This sprint, a field
marked `localized: true` renders a small **locale tab strip** directly above its input — `[Tiếng Anh]
[Tiếng Việt]` — and the input below edits the value for the selected locale. Switching tab swaps which
locale string you edit; the field label above stays exactly as today (Vietnamese, e.g. "Nội dung",
"Mô tả"). Works identically for one-line `text` and multi-line `textarea`.

**Why tabs (not two side-by-side inputs):** settings pages have MANY fields (and localized ones are often
nested inside arrays/objects, repeated per item). Two stacked inputs would double the height of every
field and make long forms exhausting to scan. Tabs keep each field at its current height — the form does
not grow — while a **"Chưa dịch" badge rendered on the locale tab itself** surfaces the missing-translation
state at a glance, without having to open the tab. This is the compact choice the requirement asks for.

**Missing-translation badge:** any non-default locale (currently `vi`) whose value is empty/missing shows a
small daisyui `badge badge-warning badge-xs` reading **"Chưa dịch"** on that locale's tab. It disappears
the moment that locale has a non-empty value. Uses `RULE-17`.

**Copy from English (included):** a tiny ghost button `Copy từ English` shown only while a non-default
locale tab is active and its value is empty. Clicking fills the current locale's input with the current
`en` value on the form (client-only, no auto-save — admin still submits). Satisfies `AC-02.3` / `RULE-18`.

**Non-localized fields are untouched:** image / number / boolean / select / slug / array-title fields
render exactly as before, with no tab strip. Only `text`/`textarea` carrying `localized: true` change.

**Locale-agnostic:** the tab strip is generated by mapping over the locale list from
`src/i18n/routing.ts` (`['en','vi']`). Adding a 3rd locale adds a 3rd tab automatically — no layout edit.

## Tech decisions

- **Reuse-first.** Reuse existing daisyui primitives and admin form components: `Input`, `Textarea`,
  `WithError`, `InputWithLabel`/`Label`, `SettingsTextInput`, `SettingsTextareaInput`, `badge badge-soft`
  pattern (as in `FilterTag`/`OrderTable`). One NEW wrapper component: `LocalizedFieldInput` (client),
  used inside `SettingTextField` and `SettingTextareaField`.
- **Single change point.** Branch on `localized` inside `SettingTextField.tsx` + `SettingTextareaField.tsx`
  (`RULE-12`). `SettingField.tsx` already spreads `{...omit(item,"type","key")}`, so `localized` flows
  through as a prop — just make sure it lands on the field component and is NOT spread onto the DOM input.
- **react-hook-form paths.** Localized value binds to nested paths `${name}.en`, `${name}.vi` (one
  `Controller` per locale), matching the stored object `{ en, vi }` (`AC-01.2`, Integration Touchpoints).
- **Backward-compatible with un-migrated data (EC-13).** If the RHF value at `name` is a plain string
  (not yet migrated), treat it as the `en` value and show empty for other locales — form must not break.
- **No new colors/spacing/fonts.** All visual values go through daisyui semantic classes already used in
  admin (`tabs`, `tab`, `tab-active`, `badge`, `input`, `textarea`, `text-error`, `btn btn-ghost btn-xs`)
  which resolve against the admin theme tokens (light + dark). See `design-system.md` → Admin tokens.

## Coverage note

This sprint has exactly one visual surface: the localized field renderer. All settings screens
(homepage, menu_page, reservation_page, layout) inherit it automatically; there are no other new screens
or states in `requirements.md`. Every field state is specified below. All screens: `[generated]`.

locale → `locale.toUpperCase()` so a 3rd locale renders without a code change to layout.

## Component spec — `LocalizedFieldInput`

**Location:** `src/components/admin/features/settings/elements/LocalizedFieldInput.tsx` (`"use client"`).

**Props:**
```
{
  control: Control;
  name: string;                 // base RHF path, e.g. "our_story.content"
  variant: "text" | "textarea"; // which input to render
  label?: string;               // VN label (unchanged)
  withLabel?: boolean;
  isRequired?: boolean;
  placeholder?: string;
  disabled?: boolean;
}
```

**Layout (top → bottom):**
1. (if `withLabel`) `InputWithLabel` wraps the whole group; VN `label` + `*` if required — unchanged.
2. Locale tab strip `role="tablist"` `tabs tabs-box tabs-xs`: one `tab` per `routing.locales`, in
   locale order with `defaultLocale` first. Each tab shows its VN label; a tab whose bound value is
   empty AND locale ≠ defaultLocale also renders the `Chưa dịch` badge inline.
3. Active locale's input:
   - `variant="text"` → reuse `SettingsTextInput` bound to `${name}.${activeLocale}`.
   - `variant="textarea"` → reuse `SettingsTextareaInput` bound to `${name}.${activeLocale}`.
   Only the active locale is visible; other locales stay mounted (or preserve value) so switching does
   not lose unsaved input. Each locale has its own `Controller` at `${name}.${locale}`.
4. (if active locale ≠ defaultLocale AND its value empty) `Copy từ English` button below/inline-end.
5. Error message under the input via existing `WithError`.

**Binding / compat:** read value from RHF; if it is a `string` (un-migrated EC-13), map to
`{ [defaultLocale]: value }` for display and write back as object on change. Never render the raw object
onto a DOM input.

**Tab strip is generated** by `routing.locales.map(...)` — no hardcoded EN/VI markup (locale-agnostic).

## States (both `text` and `textarea`)

| State | Appearance |
|---|---|
| Default (tab EN active) | tab strip, EN tab `tab-active`, input shows `en` value |
| Tab VI active | VI tab `tab-active`, input shows `vi` value |
| Hover on inactive tab | daisyui `tab` hover (theme) — no custom color |
| Focus in input | daisyui default focus ring on `input`/`textarea` (theme) |
| Disabled | tabs + input non-interactive; pass `disabled` to daisyui input (`disabled:` styles from theme) |
| Empty VI (untranslated) | `Chưa dịch` `badge badge-warning badge-xs` on VI tab; `Copy từ English` visible when VI active |
| Both EN+VI filled | no badge, no Copy button |
| Error (isRequired, default locale empty) | active input gets `input-error`/`textarea-error`; `text-error` message under it |
| Un-migrated string value (EC-13) | renders as EN value, VI empty + badge; no crash |
| Textarea variant | identical layout; input area is `textarea` `rows=5` (multi-line) — `AC-01.3` |

## Non-localized fields — confirm UNCHANGED

`SettingField.tsx` router untouched for `number`/`boolean`/`image`/`object`/`array`/`select`. For `text`
and `textarea`, when `localized` is falsy the field renders exactly as today (single `SettingsTextInput` /
`SettingsTextareaInput`, no tab strip). Array-title / sub_title (`[{text}]`, ASM-10) are never marked
localized, so they always render the single-input path. Config `config_type='app'` forms are unaffected.

## Design AC (verifiable)

```
DAC-01 [localized text field]: a text field with localized:true renders a role="tablist" (tabs tabs-box)
        with one tab per routing.locales; count(tabs) === routing.locales.length. (AC-01.1, locale-agnostic)
DAC-02 [textarea]: a textarea field with localized:true renders, per active locale, a <textarea> (not a
        one-line <input>). (AC-01.3)
DAC-03 [non-localized]: a text/textarea field WITHOUT localized renders exactly one input and NO tablist.
        (AC-01.4) Snapshot/DOM: no element with role="tablist" inside the field.
DAC-04 [label VN preserved]: the field label text equals the metadata `label` verbatim (Vietnamese); no
        translation of the label. Only locale tabs are added. (AC-01.5, RULE-13)
DAC-05 [badge missing]: when the non-default locale value is empty/missing, a badge with text "Chưa dịch"
        (class contains badge-warning badge-xs) appears on that locale tab. (AC-02.1, RULE-17)
DAC-06 [badge absent]: when all locales have non-empty values, no "Chưa dịch" badge is rendered. (AC-02.2)
DAC-07 [copy]: clicking "Copy từ English" while a non-default locale tab is active sets that locale input
        value to the current en value on the form (no network/save call fired). (AC-02.3, RULE-18) Copying
        an empty en → empty value, no error. (EC-15)
DAC-08 [save shape]: submitting writes value as object { en, vi } for the localized field; non-localized
        fields keep their prior shape. (AC-01.2) Verified via form onSubmit payload.
DAC-09 [compat string]: rendering with a plain-string value (un-migrated) does not throw; the string shows
        under the default-locale tab, other locales empty. (EC-13)
DAC-10 [tokens only]: no hardcoded hex/px in the component — colors/spacing via daisyui classes (tabs, tab,
        tab-active, badge*, input/textarea, text-error, btn btn-ghost). Grep: no `#` hex, no inline style.
DAC-11 [a11y contrast/focus]: active tab, badge text, and input text meet ≥4.5:1 against their background
        in BOTH admin light and dark themes (daisyui semantic pairs guarantee this); input + tabs keep a
        visible focus ring (no outline:none). (NFR-06)
DAC-12 [responsive]: at 360px width the tab strip + input do not overflow horizontally (tabs wrap or
        shrink via tabs-xs; input is w-full). No horizontal scrollbar on the field container.
DAC-13 [locale-agnostic layout]: adding a 3rd entry to routing.locales renders a 3rd tab with no change to
        LocalizedFieldInput layout code. (NFR-05)
```
