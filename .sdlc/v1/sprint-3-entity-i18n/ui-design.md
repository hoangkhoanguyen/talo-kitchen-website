# PART 1 — HUMAN REVIEW

## Concept (plain description)

Sprint-2 put a tab strip around a **single** settings field. Sprint-3 is different: an entity form has
**many translated text fields at once** (product: `title`, `allergenInfo`, `subDescription`, `description`;
category: `name`, `description`; addon: `name`) mixed with **non-translated** fields (`slug`, `price`,
`priority`, `isActive`, images, category, related). Putting a per-field tab strip on every field would
clutter a long form and let the locales of different fields drift out of sync.

So sprint-3 uses **one master language tab strip per form** — `[Tiếng Anh] [Tiếng Việt]` — that governs the
**whole group of translated fields together**. Switching the tab swaps every translated field on the form to
the value for that locale simultaneously; the admin fills all English fields, flips to `Tiếng Việt`, fills
all Vietnamese fields. **Non-translated fields live OUTSIDE the tab-controlled region** and never change when
the tab changes — they are shared across locales (RULE-02, AC-01.3).

Three surfaces, same pattern:

1. **Product edit page** (`ProductEditForm` + `AddonsEditor`, both under `ProductDetailsProvider`): a single
   master tab strip controls the "Thông tin cơ bản" translated fields AND every addon `name` field lower on
   the page. The active locale is shared page-wide via the product context, so the "Addons" card follows the
   same tab as the basic-info card (one control, many fields, across two cards).
2. **Product create modal** (`CreateProduct`): only `title` is translated (slug/category are shared) → a
   compact tab strip above the title input, with local `activeLocale` state.
3. **Category create modal** (`CreateCategory`): only `name` is translated (slug shared) → tab strip above
   `name`, local `activeLocale` state.
4. **Category edit modal** (`UpdateCategory`, a SEPARATE file from create): has both `name` and a
   `description` Textarea → tab strip controls BOTH `name` + `description`. This edit modal is the **only
   place** category `description` EN/VI is entered (the create modal has no description field). Local
   `activeLocale` state.

**Missing-translation badge:** on a non-default locale tab (currently `vi`), a `badge badge-warning badge-xs`
reading **"Chưa dịch"** appears when that locale is missing content for the group — defined as: at least one
translated field in the group is empty for that locale while its English counterpart is non-empty. It clears
as soon as the group is fully translated (RULE-17, AC-03.1/03.2).

**Copy từ English (optional, included):** while a non-default locale tab is active, a `btn btn-ghost btn-xs`
"Copy từ English" fills every translated field of the group for the active locale from the current English
values (client only, no auto-save — admin still submits). For addons, copies each addon's English name into
the active locale (RULE-18, AC-03.3).

**Layout separation (translated vs shared):** in the product "Thông tin cơ bản" card, `slug` currently sits
between `title` and `allergenInfo`. It is moved OUT of the tab-controlled block (rendered as a shared field,
e.g. directly under the tab-controlled group, still inside the same card) so the tab strip cleanly wraps only
`title / allergenInfo / subDescription / description`. A subtle divider/spacing separates the two regions so
the admin sees "these change with language / these don't".

**Locale-agnostic:** the tab strip is generated by mapping `routing.locales` (defaultLocale first), exactly
as sprint-2. Adding a 3rd locale adds a 3rd tab with no layout edit (RULE-20, NFR-06).

## Tech decisions

- **Reuse-first.** Reuse existing admin form primitives unchanged: `ProductTitleInput`,
  `ProductAllergenInfoInput`, `ProductSubDescriptionInput`, `ProductDescriptionInput` (all presentational
  `value/onChange/error`), the addon `name` inline input in `AddonsEditor`, `InputWithLabel`, `Label`,
  `WithError`, `Input`, `Textarea`, and the daisyui `tabs`/`badge`/`btn` classes. Reuse the sprint-2 visual
  contract verbatim so the two sprints look like one app.
- **One NEW shared component:** `LocaleTabStrip` (client) — a presentational tab strip driven by
  `activeLocale` / `setActiveLocale`, a per-locale `missing` flag, and an optional `onCopyFromDefault`
  handler. It renders ONLY the strip (tabs + badge + Copy button); it does not own any input. This is the
  group-level analogue of sprint-2's field-level `LocalizedFieldInput` and is used by all three forms.
- **Shared active-locale for the product page:** add `activeLocale` + `setActiveLocale` to
  `ProductDetailsProvider` context (or a tiny sibling context) so `ProductEditForm` and `AddonsEditor` share
  one selector. Modals keep local `useState`.
- **react-hook-form nested paths (RULE-19):** translated inputs bind to `translations.${activeLocale}.${field}`
  — e.g. `translations.en.title`, `translations.vi.description`; addon names bind to
  `addons.${index}.translations.${activeLocale}.name`. Switching locale only changes the Controller `name`;
  RHF keeps the other locale's value in form state (no data loss on switch). Non-translated fields keep their
  existing flat paths (`slug`, `price`, …) untouched.
- **Backward-compatible with un-migrated form data (EC-05):** if the form is opened for an entity that has no
  `vi` row yet, `translations.en.*` seeds from the base columns and `translations.vi.*` is empty → the `vi`
  tab shows the "Chưa dịch" badge; nothing crashes. If a legacy value arrives as a plain string, treat it as
  the default-locale value (same rule as sprint-2 compat).
- **No new colors/spacing/fonts.** Every visual value is a daisyui semantic class already in the admin theme
  (see `design-system.md` → Admin tokens). Works in admin light AND dark.

## Coverage note

Screens/states in `requirements.md` covered here: product edit page (Story-01, Story-03), product create
modal (Story-01), category create modal + category edit modal (Story-02.1), addon rows in `AddonsEditor` (Story-02.2/02.3),
missing-translation badge (Story-03.1/03.2), Copy from English (Story-03.3). Stories 04–07 (user-facing
resolve, cart API, migration/seed, cache) have **no admin UI surface** — they are service/data work, no
screen. All admin screens: `[generated]` (extracted from existing admin daisyui style; none external).

## Component spec — `LocaleTabStrip` (NEW, shared)

**Location (suggested):** `src/components/admin/features/products/form-elements/LocaleTabStrip.tsx`
(`"use client"`). Presentational — owns no form state.

**Props:**
```
{
  locales: readonly string[];        // routing.locales, defaultLocale-first
  defaultLocale: string;             // routing.defaultLocale
  activeLocale: string;
  onChange: (locale: string) => void;
  isMissing?: (locale: string) => boolean;   // group-level: true → show "Chưa dịch" (non-default only)
  onCopyFromDefault?: () => void;            // optional; when omitted, no Copy button
  showCopy?: boolean;                        // parent decides (active != default && group empty)
  className?: string;
}
```

**Render:** `role="tablist"` `tabs tabs-box tabs-xs`; one `button role="tab"` per locale (defaultLocale
first) → `tab` / `tab tab-active`; on a non-default locale where `isMissing(locale)` → inline
`badge badge-warning badge-xs` "Chưa dịch"; if `showCopy` → trailing `btn btn-ghost btn-xs text-primary`
"Copy từ English" calling `onCopyFromDefault`. All type=`button` (never submits the form).

## Screen specs

### A. Product edit page — `ProductEditForm.tsx` + `AddonsEditor.tsx`

- Add `activeLocale` / `setActiveLocale` to `ProductDetailsProvider` (default = `routing.defaultLocale`).
- **"Thông tin cơ bản" card:** render `<LocaleTabStrip>` directly under the `card-title` "Thông tin cơ bản".
  Below it, the **tab-controlled group** (unchanged input components, dynamic Controller `name`):
  - `translations.${activeLocale}.title`   → `ProductTitleInput`
  - `translations.${activeLocale}.allergenInfo` → `ProductAllergenInfoInput`
  - `translations.${activeLocale}.subDescription` → `ProductSubDescriptionInput`
  - `translations.${activeLocale}.description` → `ProductDescriptionInput`
  - Then a **divider** (`border-t border-base-300 pt-4` or `divider`) and the **shared** `slug` field
    (`SlugInput`, path `slug`, moved out of the tab group). Slug's "generate from title" reads
    `translations.${defaultLocale}.title` (English is the canonical/base — RULE-06).
- **"Thông tin khác" card (right column):** UNCHANGED — `isActive`, `priority`, `categoryId`, `price`,
  related products are all shared / non-translated, outside the tab strip.
- **"Addons" card:** each row's `name` input binds to `addons.${index}.translations.${activeLocale}.name`
  (follows the page-shared `activeLocale`). Addon `isActive` and `price` stay shared (unchanged). No second
  tab strip inside the addon card — the master strip governs it.
- **Copy từ English (page-level):** when `activeLocale !== defaultLocale`, "Copy từ English" copies all four
  basic-info fields + every addon name from `translations.en.*` into `translations.${activeLocale}.*`.
- **Badge (`isMissing`):** for a non-default locale, true when any of {title, allergenInfo, subDescription,
  description} OR any addon name is empty for that locale while its English value is non-empty.

### B. Product create modal — `CreateProduct.tsx`

- Local `const [activeLocale, setActiveLocale] = useState(routing.defaultLocale)`.
- `<LocaleTabStrip>` above the title input; title binds to `translations.${activeLocale}.title`.
- `slug` and `categoryId` remain shared (outside the strip), unchanged. Slug-generate reads
  `translations.${defaultLocale}.title`.
- Compact: strip is `tabs-xs`; modal width `w-md` unchanged; no horizontal overflow.

### C. Category create modal — `CreateCategory.tsx`

- This modal has ONLY `name` + `slug` (no description field — confirmed in code).
- Local `const [activeLocale, setActiveLocale] = useState(routing.defaultLocale)`.
- `<LocaleTabStrip>` above the `name` input; `name` binds to `translations.${activeLocale}.name`.
- `slug` stays shared (outside the strip), unchanged. Slug-generate reads
  `translations.${defaultLocale}.name`. Modal width `w-sm` unchanged.

### D. Category edit modal — `UpdateCategory.tsx` (SEPARATE file from CreateCategory)

- This is a distinct file (`src/components/admin/features/categories/UpdateCategory.tsx`) with `name`, `slug`
  AND a `description` Textarea. It is the **only** place category `description` EN/VI is entered.
- Local `const [activeLocale, setActiveLocale] = useState(routing.defaultLocale)`.
- `<LocaleTabStrip>` above the translated group; the strip controls BOTH translated fields together:
  - `name` → `translations.${activeLocale}.name` (Input, "Tên danh mục")
  - `description` → `translations.${activeLocale}.description` (Textarea `rows={3}`, "Mô tả")
- `slug` stays shared (outside the strip), unchanged; slug-generate reads
  `translations.${defaultLocale}.name`.
- Loading state (`categoryId && isLoading` spinner) unchanged. `Chưa dịch` badge on the `vi` tab when name
  or description is empty for `vi` while its English value is non-empty. "Copy từ English" copies both fields.
- Modal width `w-sm` unchanged.

## States (all three surfaces)

| State | Appearance |
|---|---|
| Default (EN tab active) | strip shown, `Tiếng Anh` `tab-active`; every translated field shows its `en` value |
| VI tab active | `Tiếng Việt` `tab-active`; every translated field (incl. addon names) shows its `vi` value |
| Switch tab | all translated fields swap locale together in one action; shared fields (slug/price/…) unchanged |
| Hover inactive tab | daisyui `tab` hover (theme) — no custom color |
| Focus in input / on tab | daisyui default focus ring (theme); keyboard: tabs are real `<button>`s, reachable + activatable by Enter/Space |
| Disabled | pass `disabled` to inputs; tabs remain to view content (or disabled per parent) |
| VI missing (untranslated group) | `Chưa dịch` `badge badge-warning badge-xs` on VI tab; "Copy từ English" visible when VI active |
| Fully translated (EN+VI filled) | no badge, no Copy button |
| Error (required EN empty) | active input `input-error`/`textarea-error` + `text-error` message (existing `WithError`) |
| New entity / no `vi` row (EC-05) | EN tab seeded from base columns, VI empty + badge; no crash |
| New addon row added then removed pre-save (AC-02.3) | removed row contributes no translation; badge recomputes over remaining rows |
| Un-migrated plain-string value | shown under default-locale tab, other locales empty; no crash |

## Non-translated fields — confirm UNCHANGED

`slug`, `price`, `priority`, `isActive`, images (`ImagesEditor`), `categoryId` (`CategorySelector`), related
products (`RelatedProductEditor`), addon `price`, addon `isActive`, and every number/boolean/url render
exactly as today, OUTSIDE the tab strip, shared across all locales. Switching the locale tab must not alter
any of them (AC-01.3, AC-04.6, RULE-02). The right-column "Thông tin khác" card is untouched.
