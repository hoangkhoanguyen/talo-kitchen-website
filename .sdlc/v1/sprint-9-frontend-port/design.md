# PART 1 — HUMAN REVIEW

## 1. Design Overview

- **1:1 UI port, new data layer.** Every component under `src/components/web/**` and every page under
  `src/app/(web)/**` is copied almost verbatim into the Payload app. Only the *data source* changes:
  Drizzle services → Payload. Visual layer (Tailwind 4 + daisyui theme tokens, fonts, component markup)
  is carried over unchanged. Rationale: architecture.md says "UI theo style app hiện tại, không hỏi lại."
- **RSC reads via Payload Local API.** Server components / `generateMetadata` call a new thin data-access
  layer (`src/lib/web/data/*`) that wraps `getPayload()` + `payload.find/findByID/findGlobalType`.
  This replaces `src/services/**` + `src/services/cached/**`. Rationale: Local API is the sanctioned
  in-process access path, no HTTP hop for RSC.
- **Client reads via custom Next route handlers backed by Local API.** Cart hydration + quick-cart need a
  *merged* product+addons shape (addons are a separate collection now), so we reproduce the two old web
  endpoints as route handlers under `(frontend)/api/**` using Local API. Client hooks keep their existing
  shape. Rationale: raw Payload REST cannot join `products` + `product-addons` in one call cheaply.
- **Order creation goes through the existing `POST /api/orders/checkout` endpoint.** The old client-side
  price computation + guest-order server action is replaced by the already-built anti-tamper checkout
  endpoint (sprint-7). The client only sends item ids/quantities/addons; the server derives all prices.
- **Reservation creation goes through Payload REST `POST /api/reservations`** (collection `create: () => true`,
  code auto-generated by hook). Replaces the old `createReservationAction`.
- **Caching = `unstable_cache` tag wrappers + Payload collection/global `afterChange`/`afterDelete`
  hooks calling `revalidateTag`/`revalidatePath`.** This preserves the old tag-based revalidation behavior
  while removing the unauthenticated `/api/revalidate-all` route.

## 2. Tech Decisions (libraries / patterns — user may override)

New npm installs into `talo-kitchen-payload` (all already proven in the old app; versions align to
React 19.2 / Next 16.3 / TS 5.7):

```bash
# runtime deps
pnpm add zustand @tanstack/react-query swiper react-datepicker react-hook-form \
  zod @hookform/resolvers nuqs sonner moment lodash clsx tailwind-merge \
  class-variance-authority @headlessui/react @iconify/react axios query-string
# styling (dev)
pnpm add -D tailwindcss @tailwindcss/postcss daisyui
# types (dev)
pnpm add -D @types/lodash @types/react-datepicker
```

Decisions:
- **Tailwind 4 + daisyui, CSS-first config** (no `tailwind.config.*`; theme tokens live in the ported CSS,
  same as old app). Tailwind CSS is imported **only** from the `(frontend)` layout so its preflight cannot
  leak into the Payload admin (`(payload)`) styles. See Risks.
- **State:** `zustand` (cart store persisted to `localStorage` + cross-tab sync, quick-cart modal store,
  UI loading store, mobile-menu store) — ported verbatim.
- **Data fetching (client):** `@tanstack/react-query` (cart product hydration, quick-cart fetch,
  checkout/reservation mutations) — ported.
- **Forms:** `react-hook-form` + `zod` + `@hookform/resolvers` (checkout + reservation forms).
- **UI libs:** `swiper` (hero/gallery/related/product-image sliders), `react-datepicker` (reservation
  date/time), `@headlessui/react` (modal), `@iconify/react` (`Icon` wrapper), `sonner` (toasts).
- **Utils:** `moment` (reservation success formatting only), `lodash` (`capitalize`), `clsx` +
  `tailwind-merge` (`cn`), `class-variance-authority` (button variants), `query-string`.
- **`nuqs`:** listed for completeness but **NOT used** by any ported web component (menu uses route params,
  not query params). Recommend **dropping** it unless a builder finds a real use. Do not install if unused.
- **Data-access pattern:** a dedicated `src/lib/web/data/` module — pure functions returning
  view-model-shaped plain objects (never leaking Payload doc internals to components), each wrapped in
  `unstable_cache` with explicit tags.

## 3. Risks / Trade-offs

- **R1 — Tailwind preflight vs Payload admin.** Tailwind's global reset must not touch `(payload)`. Mitigation:
  import `@import "tailwindcss"` only inside `(frontend)/styles.css`, which is imported only by the
  `(frontend)` layout. Verify the admin panel still renders after install. If bleed occurs, scope with
  a `.website` wrapper class + Tailwind `important`/`@layer` as fallback.
- **R2 — `reservations.numberOfPeople` is `number` but the UI submits a range string.** BLOCKING schema
  bug (see §12 Schema Fixes). The reservation form's `size_options` are strings like `"1-6"`, `"7-10"`.
  Posting to a `number` field will fail validation. Must change the collection field to `text` (or `select`).
- **R3 — R2 dev bucket / public-URL mismatch → images may 404 in dev.** Known, non-blocking for layout.
  Data-access must resolve `media` relationships to a URL and degrade gracefully (empty `imageUrl` →
  components already handle `""`). Flag only; do not block.
- **R4 — Addons moved from embedded to a separate collection.** Any read that needs product + active addons
  is now 2 queries. Encapsulated in the data-access layer; cart/quick-cart route handlers do the join.
- **R5 — Checkout request/response contract changed.** Client no longer computes/sends per-item prices;
  server derives them. `CheckoutProvider` + `useCreateOrder` must be rewritten to the new
  `POST /api/orders/checkout` body + `{success,data:{order,items,customer}}` response. Success UI reads
  `data.data.order.code`.
- **R6 — Product `id` type change (int → Payload id).** Old cart store persists `productId: number`.
  Payload ids are numbers in Postgres adapter, so existing localStorage carts remain compatible; but a
  user with a stale cart referencing a legacy id that no longer maps will simply get filtered out
  (handled by `useGetCartProducts` `.filter(Boolean)`). Acceptable.
- **R7 — `force-dynamic` in old layout.** Old `(web)/layout` used `export const dynamic = "force-dynamic"`.
  We instead rely on cached data-access + tag revalidation so pages can be static/ISR. Keep layout dynamic
  only if a builder hits a Payload-in-RSC caching edge; prefer tag-based.

## 5. Data Model (read shapes consumed by the frontend)

No new persisted entities. This sprint READS the collections/globals built in sprints 2–6. Relevant
shapes and how the data-access layer maps them:

### `products` (collection)
Fields used: `id, title, slug, priority, category(rel→categories), allergenInfo, subDescription,
description, price, relatedProducts(rel hasMany→products), isActive, images[] {image(rel→media),
altText, isPrimary, sortOrder}`.
- **Addons are NOT on products** — they live in `product-addons` (`product` rel, `name, price, isActive,
  sortOrder`). Any "product details" read must issue a second query for active addons sorted by `sortOrder`.
- **Image URL**: resolve `images[].image` (media relationship) → `media.url` via `resolveMediaUrl`. Sort by
  `sortOrder asc`; "primary/first" image = `images[0]` after sort (matches old `limit:1 orderBy sortOrder`).

### `categories` (collection)
`id, slug, name, isActive, description`. Menu lookups: `where slug == categorySlug AND isActive == true`.

### `product-addons` (collection)
`id, product(rel), name, price, isActive, sortOrder`. Read `where product == productId AND isActive == true`,
`sort: sortOrder`.

### `reservations` (collection) — WRITE (public create)
Frontend POST body: `{customerFullName, customerPhone, numberOfPeople, arrivalTime, arrivalDate, note}`.
`code` auto-generated (hook), `status` defaults `scheduled`. **`numberOfPeople` schema fix required — §12.**

### `orders` (+ `order-items`, `order-item-addons`) — WRITE (via checkout endpoint only)
Not created directly; see §6 checkout contract. Response snapshots surfaced to the success UI:
`order.code, order.totalPrice, items[].productName/price/quantity/totalPrice`.

### Globals (read)
- `homepage` → `seo, hero, contact, gallery, reviews, our_story, why_choose_us`
- `menu-page` → `seo, hero, new_product, why_choose_us, food_categories{title,sub_title,categories_to_show[]{key,label,page_title}}`
- `reservation-page` → `seo, hero, booking`
- `layout` → `header, footer, floating_actions`
- `order-settings` → `shipping{methods[]{method,label,description,isDefault}, rules[]{minOrderValue,shippingFee,description}}, closed_mode`
- `reservation-settings` → `reservation{size_options[]{value}}, closed_mode`

> View-model note: the old code read `config.value.<x>`. Payload globals expose fields at the top level
> (no `.value` wrapper). Data-access functions must return the global object directly and ported components
> must be adjusted from `configs?.value.hero` → `configs?.hero` (and `seo` from `value.seo` → `seo`).

## 6. API Contracts

### 6.1 `GET /api/products/ids?ids=1,2,3`  (NEW route handler — cart hydration)
- Auth: none (public). Runtime: Local API via `getPayload`.
- Query: `ids` = comma-separated numeric ids. Empty/missing → `{ products: [] }`.
- Behavior: `payload.find({collection:'products', where:{ id:{in:ids}, isActive:{equals:true} }, depth:1,
  sort:'-priority'})` + for the returned ids `payload.find({collection:'product-addons',
  where:{ product:{in:ids}, isActive:{equals:true} }, sort:'sortOrder'})`; merge addons per product.
- Success 200:
  ```json
  { "products": [ { "id":1, "slug":"...", "title":"...", "price":0, "imageUrl":"...",
                    "category":"...", "addons":[ {"id":9,"name":"...","price":0} ] } ] }
  ```
- Error 500: `{ "products": [], "error": "..." }` (wrapped by `withError`). Never throws to client.

### 6.2 `GET /api/products/quick/[id]`  (NEW route handler — quick-cart modal)
- Auth: none. Local API.
- Behavior: fetch active product by id (`title, price, allergenInfo, category.name, first image url`) +
  active addons.
- Success 200: `{ "product": { "id","title","price","allergenInfo","category","imageUrl",
  "addons":[{"id","name","price"}] } | null }` (null when not found / inactive → EC-02).

### 6.3 `POST /api/orders/checkout`  (EXISTING Payload endpoint — used by checkout)
- Auth: none (public). Content-Type: `application/json`.
- Request body (`CheckoutBody`):
  ```json
  { "firstName","lastName","customerPhone","orderType":"delivery|pickup","orderTypeLabel",
    "paymentMethod":"cash","deliveryAddress","addressNote","note","shippingFee":0,
    "items":[ {"productId":1,"quantity":2,"note":"","addons":[{"addonId":9,"quantity":1}]} ] }
  ```
- Success 200: `{ "success":true, "data":{ "order":{...,"code"}, "items":[...], "customer":{...} } }`.
- Errors (client must read `code` and react):
  - 400 `{success:false, code:"INVALID_BODY", error}` (EC-11/EC-12/EC-13 shape errors).
  - 400 `{success:false, code:"DELIVERY_ADDRESS_REQUIRED", error}` (EC-08 delivery w/o address).
  - 4xx `{success:false, code:"INVALID_ORDER_DATA" (or validateOrderData's code), error}` — product/addon
    missing/inactive/price-drift (RULE-16 anti-tamper). Client → toast + `window.location.reload()`.
  - 500 `{success:false, code:"ORDER_CREATE_FAILED", error}` (EC-14 transaction rollback).

> The client stops sending prices; server derives them. `useCreateOrder`/`CheckoutProvider` rewritten to
> build `items` from the cart store (`productId, quantity, note, addons:[{addonId,quantity}]`) and pass
> `shippingFee` computed from `order-settings.shipping.rules`.

### 6.4 `POST /api/reservations`  (EXISTING Payload REST — collection public create)
- Auth: none (`create: () => true`). Body: `{customerFullName, customerPhone, numberOfPeople,
  arrivalTime:"HH:mm", arrivalDate:"YYYY-MM-DD", note}`.
- Success 201: `{ doc: { id, code, status:"scheduled", ... }, message }`. Client reads `doc.code`.
- Error 400: Payload validation error `{ errors:[{message,...}] }` (EC-15/EC-16 required-field /
  arrivalTime-format / numberOfPeople). Client → `toast.error`.

## 9. NFR Design

- **NFR-01 (Performance):** All RSC reads go through `lib/web/data/*` wrapped in `unstable_cache` with the
  tags in §10; cache is invalidated only by write hooks, so pages serve from cache between admin edits.
  Lookups use existing indexes: `products.slug` (unique idx), `products.category` (idx), `categories.slug`,
  `product-addons.product` (idx), `products.id`. Google reviews cached 8h (time-based). `depth` kept
  minimal (1 for lists, 2 for dish detail) to avoid over-fetching relationships.
- **NFR-02 (Security):** `orders` collection `create: () => false` — the only creation path is the
  anti-tamper `POST /checkout` endpoint. The unauthenticated `/api/revalidate-all` route is NOT ported;
  revalidation is triggered exclusively by server-side collection/global hooks. Route handlers 6.1/6.2 are
  read-only and only expose active products.
- **NFR-03 (SEO/branding):** `constants/web/app.ts` (`APP_NAME/URL/DESCRIPTION/ICONS`) + per-page
  `generateMetadata` ported: canonical per route, OG `en_US`/`type:website`/1200×630, brand string
  "TALO Kitchen & Lounge", `APP_ICONS` reused on every page (PNG-first) so no page reverts favicon,
  Restaurant JSON-LD + GTM scripts in layout, `robots`/`verification` carried over.
- **NFR-04 (Admin isolation):** Tailwind is imported only from `(frontend)/styles.css`; `(payload)` layout
  keeps `custom.scss`. Post-install smoke test: load `/admin`, confirm no reset regressions.

## 12. Schema Fixes Needed in EARLIER Sprints (must resolve before/with this sprint)

- **SF-1 (BLOCKING) — `reservations.numberOfPeople`.** Currently `type:'number', min:1`
  (`talo-kitchen-payload/src/collections/Reservations.ts`). The reservation UI submits a **range string**
  from `reservation-settings.size_options` (e.g. `"1-6"`, `"7-10"`) and the OLD DB column was
  `varchar(20)`. A number field rejects these. **Fix: change to `type:'text'`** (or `type:'select'` with
  `hasMany:false` sourced from settings — but options are dynamic, so `text` is simplest and matches legacy).
  Also relax/remove `min`. This aligns migrated data (strings) and the form. Owner: whoever owns the
  Reservations collection (sprint-4/5); must land before the reservation page task (Wave D).
- **SF-2 (verify) — media public URL in dev.** Confirm `storage-s3`/`media.url` yields a reachable URL;
  if the R2 dev bucket/public-URL mismatch stands, images 404 in dev only (non-blocking, R3). No code fix
  in this sprint beyond graceful `""` fallback.
